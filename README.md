# ヒストリカル・トレード

いつの相場かわからない1年で、日米欧の株・暗号資産・先物を売買して腕を競う投資ゲームです。

遊べるデータは2種類あります。

| データ | 誰が遊べるか | 中身 |
|---|---|---|
| 架空銘柄 | 誰でも | 数式モデルで生成した架空の会社・暗号資産・ETF・先物・為替（約110銘柄・30年分）。実データは一切使っていない |
| 実データ | 招待コードを使った身内だけ | 日経225・S&P500・EURO STOXX 50 の構成銘柄、主要な暗号資産、連動 ETF（約790銘柄） |

実データ（Yahoo Finance 由来）は再配布できないため、一般公開は架空銘柄だけにしています。ランキングもデータごとに別です。

- 価格は「円換算 → 開始日の終値=100 の指数」で表示し、ランク戦では終了まで実日付・実価格を出さない
- 翌営業日の始値で約定（指値は値幅で判定）、手数料・スプレッド・為替手数料、年内損益通算の税、配当
- 全銘柄を均等に買い持ちしたベンチマークとの差（%ポイント）がスコア。月間シーズンの平均でランキング
- ランク戦の放棄は「その時点の成績」と「-20pt」の低い方で確定（放棄で得をしない）
- 信用取引（株・ETF・暗号資産の買い・売り）と先物（株価指数・商品・債券・為替の13銘柄、満期なしのつなぎ足）。
  毎日の終値で値洗いし、証拠金が足りなくなると追証→強制決済。税は「株等」と「先物」を別々に通算
- 練習モード（ランキング対象外）：実データは期間を選べて実日付・実価格も表示できる。架空銘柄は期間ランダム
- 架空銘柄では実日付は一切出さず、終了後に「架空暦 ○年目」を表示

ルールの全文はアプリの `/rules` にあります。

## 技術構成

Next.js 16（App Router）/ TypeScript / Postgres + Drizzle / Auth.js（Google・GitHub）/ lightweight-charts / Vitest / Playwright

```
src/lib/engine/   純粋TSのゲームエンジン（DB非依存・ユニットテストの中心）
src/lib/game/     サーバー側：シナリオの作成・進行・注文・終了処理と、クライアント向けの表示データ
src/app/api/      Route Handlers（入力は zod で検証）
src/config/game.ts  初期資金・コスト・税率などの設定
scripts/import/   実データの取り込み（DataProvider で差し替え可能）
scripts/synthetic/  架空データの生成モデル（局面切り替え・3層因子・ジャンプ・決算の窓・配当・祝日・為替）
```

公平性のため、シナリオの状態と未来の価格はすべてサーバーが持ちます。クライアントには「k 日目」と指数だけを返し、
実日付・実価格・指数化の基準値は `isRevealed`（ランク戦の終了後、または練習モードで表示を選んだとき）のときだけ付けます。

## ローカルで動かす

```bash
npm install
cp .env.example .env.local   # DATABASE_URL などを設定
cp .env.local .env           # スクリプト（drizzle-kit・取り込み）も同じ設定を読む
npm run db:migrate

# 指数構成銘柄の一覧（universe.json はコミット済み。構成変更時だけ再生成）
npm run import:universe

# 市場データの取り込み（全銘柄で数十分・約400万行。再実行すると差分だけ更新）
npm run import:data
npm run import:data -- --symbols AAPL,7203.T,BTC-USD   # 一部だけ

# 架空データの生成（約1分・約70万行。シードが同じなら同じ相場になる）
npm run generate:synthetic
npm run generate:synthetic -- --add-missing   # あとから足した銘柄（先物など）だけを追加する

npm run dev
```

招待コードは、`ADMIN_EMAILS` に書いたメールアドレスでログインした管理者が `/admin/invites` で発行します。
受け取った人が設定画面で入力すると、実データで遊べるようになります。

OAuth を設定しなくても、`.env.local` に `AUTH_DEV_LOGIN=1` を入れると名前だけで入れるテストログインが使えます
（Vercel 上では常に無効）。

```bash
npm run lint && npm run typecheck && npm test
PW_CHROMIUM=/path/to/chromium npm run test:e2e   # 開発サーバーを自動で起動。データ取り込み済みのDBが必要
```

E2E はランク戦を最初から最後まで通し、終了前の API レスポンスに実日付や基準値が含まれないことも確認します。

## 既知の制約

- **実データのライセンス**：取り込みは Yahoo Finance（非公式 API）で、利用規約上は個人利用が前提です。招待制で身内に限っていますが、
  規約上完全に問題がないとは言えません。広く公開するなら、再配布可能な有料データ源の `DataProvider` を
  `scripts/import/providers/` に追加して切り替えてください。
- **PER・PBR**：過去時点の決算データを無料で取れないため、テーブルと表示だけ用意してあり、現在は「—」になります。
  `DataProvider.fetchFundamentals` を実装したデータ源に切り替えると埋まります（決算発表日より前の数字は出しません）。
- **生存者バイアス**：銘柄は現在の指数構成銘柄です。`index_memberships` は期間（from/to）を持てるので、
  当時の構成銘柄を出せるデータ源に切り替えたときに移行できます。
- **DB 容量**：日足は単精度で持ち、主キー以外の索引を付けていないので、実データと架空データを合わせて約390MB です。
  Vercel 経由で作った Neon の Free プランは上限が 512MB（`neon.max_cluster_size`）なので、余裕は約120MB です。
  足りなくなったら、`--from` で実データの取り込み開始年を遅らせてください。
- **先物の実データ**：Yahoo の連結先物（期近のつなぎ足、`scripts/import/universe/futures.ts`）をそのまま使っています。
  乗り換えの日を見分けられないので、さかのぼった補正はしておらず、乗り換えの日に価格が飛ぶことがあります（特に商品）。
  ユーロ・ストックス50は先物が取れないので指数で代用しています。WTI原油はマイナス価格の期間（2020年春）を含むシナリオから外します
  （`src/config/game.ts` の `EXCLUDED_PERIODS`）。
